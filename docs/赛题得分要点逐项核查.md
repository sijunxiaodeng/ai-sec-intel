# 赛题得分要点逐项核查与补强

核查日期：2026-10-14。依据是用户提供的奇安信赛题九 PDF、六模块自查清单、当前代码及实际运行证据。本文中的“已有”表示可定位到实现，“本轮补齐”表示已增加可验收的代码；两者都不自动代表比赛得分或线上启用。

## 先校正评分口径

赛题正文要求 Agent 技术及自主决策、编排、工具调用，但不指定 LangGraph、AutoGen 等具体框架；初赛评分表仍有“基本使用 Agent 框架”要求。四类风险是参考分类，正文明确不作为评分依据。CNVD、指定付费资产平台、SimHash、UA 轮换、某一 reranker、Prometheus/Grafana 品牌都不是 PDF 单独指定的硬性项。

决赛富化合格是**准确率 ≥80% 且召回率 ≥70%**，良好是两者均 ≥90%，优秀是两者均 ≥95%。决赛问答合格是**准确率 ≥75% 且响应 ≤5s**，良好是 ≥90% 且支持多跳，优秀是 ≥95% 且推理链可解释。PDF 要求运行稳定性，但没有指定“七天”这一硬期限；七天持续运行是有价值的补证方案。

## 已有真实快照能证明什么

旧 Actions run `38369832431` 的 artifact 已从 GitHub 获取并校验，迁移副本保留原来源、融合记录、文档、基线和游标。本文新增监测审计使用这份本地副本，固定评估时间 `2026-10-14T00:00Z`：

- 13 个配置来源、8 类；迁移后按当前规则/哈希有效正例计算，确有 8 类来源内容。这是规则判断和历史存档覆盖，没有替代独立 AI 相关性抽审。
- OSV、Ollama、Transformers 来源记录为 0，不能把它们计作实际有效来源。
- 精确实时 AI 来源样本 35 条，其中 27 条延迟 ≥6 小时。包含文档及跨源重复，不能称为 35 个独立 CVE；此处是本项目严格 `<6h` 的违约口径，比赛 `≤6h` 口径另有明确字段。
- 所有来源都缺少完整七天采集历史。旧存档的新鲜度随固定评估时间显示 stale，不代表最新版本当前在线故障。

## 需要外部条件，与仍待开发项

真正无法仅凭仓库修改完成的是：持续在线部署机器和服务地址、实际快照交付启用、资产平台账户/额度或真实导出、授权标准正文、合法隔离的 PoC 实验环境、独立人工评审、持续运行时间、正式负载与恢复演练。令牌和付费模型 key 只能在环境/仓库 Secrets 中配置，不要发到聊天或提交进仓库。

国内来源适配、更广的 PoC 元数据搜索、reranker、通用资料多轮会话、个性化推荐、问答埋点、完整统一日志、镜像发布工作流仍是开发缺口，不应冒称全部依赖外部条件。优先顺序建议：先完成真实部署与历史补采闭环，再准备本地语义模型并独立评测问答/富化，最后围绕真实失败样本决定这些增强项；新功能的存在不能代替效果数据。
