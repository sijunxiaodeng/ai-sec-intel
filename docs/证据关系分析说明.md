# 第十三步：证据关系与限定跨文档分析

本步继续任务 C，从资料摘录推进到有前提、有来源、有边界的综合。当前先覆盖「间接提示注入」一个主题，不宣称完成所有论文/漏洞的通用知识图谱或自由多跳推理。

## 如何使用

1. 启动 `python main.py`，打开本机系统并进入「安全资料库」。
2. 点击「填入关系示例」，再点「按证据回答」。此按钮切换到关系分析、清空旧资料选择和类型筛选，默认使用已核对的论文 HTML 全文与 NIST 框架。
3. 示例问题：`比较论文和 NIST 对间接提示注入的机制解释、防护建议及局限。`
4. 在回答下展开「来源事实与限定条件」，查看事实、资料版本和引用，再在「原文证据」核对正文及页码。

还可询问：`间接提示注入的触发条件和可能影响是什么？`、`NIST 与论文都谈到间接提示注入，能算两次独立复现吗？`。只选论文、只筛选标准或缺少资料时，程序明确拒绝完成所需跨文档综合，不补造前提。

切回「原文摘录」可继续问其他主题或政策。关系分析不判断具体 CVE、产品版本、资产受影响、法规适用性或未测量的防护成功率。

## 来源及关系

资料范围为 [arXiv 2302.12173 HTML](https://arxiv.org/html/2302.12173) 实际版本 `2302.12173v2` 与 [NIST AI 600-1 (2024) PDF](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。论文按章节定位；NIST 物理第 15 页提供风险概述、第 37 页提供 MS-2.7-007 建议、第 59 页列出参考文献。物理页码与印刷页码不同；本轮额外目视核对了物理第 37、59 页的表格/参考文献，前一步已核对第 15 页。

11 条中文关系说明涵盖机制、条件、可能影响、潜在防护、局限、评估建议和引用关系。全图有 14 个节点（主题 1、文档 2、事实 11）、23 条边；这些边包括主题与事实、文档支持事实，以及一条文档引用，不等于 23 条攻击因果关系。

四条限定综合路径：

| 路径 | 所用前提 | 输出边界 |
| --- | --- | --- |
| A1 机制对照 | 论文的数据/指令边界说明 + NIST 的直接/间接路径定义 | 比较描述角度，不把两者作为独立实验 |
| A2 条件与可能影响 | 论文机制、检索/读入条件和可能影响 + NIST 概述 | 概念风险路径，不判定具体应用已受影响 |
| A3 防护方向与评估边界 | 论文潜在过滤方向及编码、规避、RLHF 局限 + NIST 红队评估建议 | 明确标为项目综合；提出待评估方向，不宣称防护生效 |
| A4 来源引用与独立性 | NIST 参考文献记录 + 对应论文 | 存在引用关系，不能只按文档篇数认定独立攻击复现；未核对每句依赖 |

来源说明与综合文字按固定核对版本整理。NIST 为自愿风险管理框架，不能将其建议解释为中国强制条款；论文中的防护讨论也不能泛化为所有后续模型的效果判断。来源事实使用 `authority/qualifier` 保留性质和限定，项目执行状态由程序另行说明。

## 原文绑定与模型角色

`enrichment/relations.json` 保存开发过程核对后的中文说明、URL、版本、范围、定位及片段 SHA256；不包含论文全文或模型草稿。该中文说明由开发过程的来源复核建立，**没有独立人类审核者确认**。这不是自动从所有新资料抽取通用关系。

每次读取先复用资料库原始响应/片段完整性检查，再核对预期来源、版本、内容范围、具体定位和文本摘要。任何绑定片段变化就关闭该事实及依赖它的综合；需重新核对后才能更新关系记录。网页本身的动态元素改变但核对片段不变，不必机械关闭同一事实。

普通刷新失败可以沿用带获取时间的旧成功存档，并明确提示旧证据。没有新版本的核对记录时，不将新文本自动套入旧中文说明。缺少任一综合前提或只有一个来源，程序返回证据不足。回答图谱仅包含与本轮事实关联且原文已返回的边；GET 图谱接口可查看全量可用关系。

问题先通过规则选择所需分析维度。配置 DeepSeek 等兼容接口时，模型可以从已有候选路径选择与排序，不能新增事实、正文、引用或自由推理结论；未知、重复或遗漏必需路径时回退。模型采用率只反映路径选择通过情况，不能当作语义审核准确率或通用智能体能力。

## 开发评测与人工复核准备

来源前提及 14 道题另写在 `questions/relations_evaluation.json`，使用原文短锚点/定位核对版本，未通过生产关系函数生成标准要点。作者已知实现，题单也在仓库公开，所以**不是独立盲测集**。

运行前确保本机服务和两份所需全文已入库：

```powershell
python -m unittest discover -s questions -p "test_*.py"
python -m questions.evaluate_relations --mode rules --output data/relations-rules.json
python -m questions.evaluate_relations --mode model --case R01 --case R05 --case R09 --output data/relations-model.json
```

`--public-output` 可另写脱敏报告；它不含完整答案和原文。完整答卷、原文和 `manual_review` 栏留在本机 `data/`。独立评审应直接核对来源，分别判断相关性、完整语义、条件保留、综合边界与引用关系，填写评审人及是否独立；自动规则只查表达/定位/图谱引用，不自动填人工分数。

本轮最终 181 项测试通过，包含原始响应篡改、片段变化、版本变化、成功更新、失败沿用、单一来源、模型越界/遗漏、不可支持的效果测量、API 及图谱证据闭合。最终规则 HTTP 14/14、模型 HTTP 3/3 通过自动检查；规则约 0.015–0.103 秒，模型约 0.75–1.03 秒。这些是本机一次请求序列，包含请求序列化、服务端工作和完整响应读取，排除浏览器渲染；不是负载测试或整个赛题五秒达标证明。

首次图谱结果包含未参与本轮正文的关系边，复核后改为只返回本轮关系，并加强每条边的证据检查。修复前后批次分别保留；最终三道模型题以修复后结果为准。本轮实际调用模型共 8 次：初始 HTTP 3、修复后 HTTP 3、浏览器示例 2；均采用了路径选择，未自由生成正文。浏览器验证没有正式计时。不得把程序输出的固定综合冒充模型自由推理。

脱敏最终答卷见 `questions/results/relations_rules_20261009.json` 和 `questions/results/relations_model_20261009.json`，过程与版本摘要见 `questions/results/relations_20261009.json`。人工语义准确率、通用多跳准确率、关系抽取精确率/召回率仍为未测量。
