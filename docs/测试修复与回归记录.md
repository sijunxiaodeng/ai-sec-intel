# 云环境测试修复与回归记录

本轮修复针对 `0e9dac4` 检出的开发回归失败和离线启动问题。赛题九 PDF 作为需求背景；本记录验证系统的工程运行，不代替赛题的独立准确率、召回率、真实采集时效和模型评测。

## 修复内容

- 主应用默认消费 B 的增量变更流，嵌入模式直接读库。关键词不裁剪同步范围，更新、撤回与游标在同一事务提交，消除离线启动错误访问 8765 和重复外部采集。
- 手动与定时监测共用采集锁，正确区分接收量、新增量和库内总量。流水线只处理数值指标，部分完成不会被终结器覆盖；启动首轮后等待配置的间隔。
- 公开资料同步保留独立入口和任务，资料摘要通过 B 的持久变更流同步。论文查询因预算轮转未完成时，保留部分状态，不误报来源断连。
- EPSS/KEV 使用各自查询时间更新。成功的空结果替换旧观测，失败保留最近成功值并记录尝试；旧读者的失败快照不能覆盖并发提交的新成功值。
- 卡片 JSON/JS 先暂存并同步落盘，备份保留到数据库提交成功。写入、替换或提交失败时恢复导出和事务；恢复失败时保留备份以供修复。
- 将旧 JSON 存储测试迁移到实际 SQLite 记录、修订、运行历史与游标断言。补齐前端 VM 状态和 B 测试的共享协议路径，保留失败、并发、迁移及安全渲染检查。

## 复现

在仓库根目录创建并激活 Python 3.12 虚拟环境，执行：

```bash
python -m pip install -r requirements-test.txt
python -m pip check
export PYTHONUTF8=1 AUTO_MONITOR_ON_START=0 AUTO_MONITOR_ENABLED=0
export B_MONITOR_ENABLED=0 B_MONITOR_ON_REFRESH=0 AUTO_INGEST_ON_COLLECT=0
export AUTO_CLASSIFY_V5=0 CLASSIFY_V5_MAX_LLM_CALLS=0 CLASSIFY_V4_MAX_LLM_CALLS=0
export DEEPSEEK_REVIEW_ENABLED=false
validation_dir=$(mktemp -d)
export MAIN_KB_DB_PATH="$validation_dir/knowledge.sqlite3"
export MAIN_DATA_DIR="$validation_dir/data"
python scripts/run_offline_tests.py --start-directory questions
python scripts/run_offline_tests.py --start-directory scripts/tests
python scripts/check_offline_demo.py
node --check web/app.js
node questions/test_article_candidates_ui.js
node questions/test_asset_observations_ui.js
node questions/test_poc_sources_ui.js
(
  cd intelligence
  INTELLIGENCE_DB_PATH="$validation_dir/intelligence.sqlite3" \
    python ../scripts/run_offline_tests.py --start-directory tests
)
```

启动离线开发演示：`python scripts/offline_demo.py`。首次自动准备隔离的合成数据，无需模型密钥或地址绕过配置。服务启动后可执行 `python scripts/check_container_integration.py --preloaded` 检查本机 HTTP 流程。
