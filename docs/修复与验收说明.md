## 验证方式

使用 Python 3.12 的独立主应用/B 虚拟环境，禁止外部 socket、关闭后台采集与模型调用。执行：

```bash
python scripts/run_offline_tests.py --start-directory questions
python scripts/run_offline_tests.py --start-directory scripts/tests
# 在 intelligence 目录，使用其独立虚拟环境：
python ../scripts/run_offline_tests.py --start-directory tests
```

回归覆盖旧快照拒绝、幂等发布、旧读连接完成/新请求换代、超过 200 条数据同步、失败不推进游标、来源修订及撤回、多进程写入、过期任务拒绝提交、索引竞态和模型引用伪造/冲突/超时回退。

2026-10-11 验证：主应用 348 项、B 模块 264 项、验收脚本 12 项，共 624 项通过；使用与 CI 相同的默认内置 B 模式和隔离数据库环境。两套依赖的 `pip check`、actionlint 1.7.7、JavaScript 和 Python 语法检查通过。

容器内置 B 和独立 B 服务两种模式的真实 HTTP 联调均通过：4 条合成漏洞及 4 份合成资料完整导入，重复导入数量不变。本云环境的容器内 DNS 无法下载依赖，因此宿主经正常 TLS 下载同一 requirements 的 wheel，再使用临时 Dockerfile 离线构建；生产 Dockerfile 未改为离线路径。不能据此声称这里已经验证标准联网构建。

`.github/workflows/system-checks.yml` 在 PR 中运行独立依赖检查和三个测试集，再启动隔离的合成数据容器，实际请求 B 查询、两次 B→A 同步和两次 B→C 同步。`scripts/check_container_integration.py` 校验完整数量与重复导入稳定性。

## 仍须完成的真实验收

1. 合并修复到 `main` 后，确认一次新的云端采集执行并成功上传快照。没有新格式快照时，镜像器拒绝以未绑定代码版本的旧快照冒充已验证交付。
2. 按 [正式数据部署与交付](正式数据部署与交付.md) 启动所选模式。Actions 可在电脑关机后采集；电脑关机时其网页/API 仍不能在线。Actions 镜像部署使用 Linux 容器；Windows 使用 Docker Desktop/WSL。
3. 固定连续观察窗口，检查真实有效数据是否覆盖至少七类来源，并分别测量发布时间→首次采集与云端快照→主库消费延迟。GitHub 的 15 分钟 cron 配置不能证明 `<6h`；保留之前所有超时记录及原基线。
4. 由未参与实现的人标注分类、富化与问答样本，固定样本后测精确率、召回率、引用支持及实际端到端耗时。模型自评和单元测试都不能替代独立验收。流程见 [固定观察期与独立评测](固定观察期与独立评测.md)。
5. 需要向量检索时另行准备本地模型；默认可使用 BM25。跨资料推理复用页面的模型配置；本轮离线测试未调用真实收费模型。
