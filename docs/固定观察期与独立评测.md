# 固定观察期与独立评测

本轮修复后的功能测试、真实采集时效和人工质量评测分别记录。测试通过不自动成为赛题达标结论；没有独立标注时，准确率、精确率和召回率保持 `null`。

## 网页验收中心

从左侧「验收中心」进入四个区域：初赛九项要求、质量复核、持续采集观察、交付证据。网页展示实际样本与计数，不自动给出比赛得分或“全部通过”。未配置材料、没有样本、没有人工复核、没有上游清单时均显示待补，不能用零或 100% 代替。

质量区域可导入 `questions.evaluate` 的完整 JSON 报告，也可下载富化事实模板。导入时冻结整批报告、题目 ID、题单摘要、模型和来源摘要；已有报告不能覆盖。已公开的开发题单始终标明公开开发集，不能改名充当盲测。评委可逐题查看问题、完整回答、引用、自动检查失败和模型回退，再填写事实正确、引用支持、条件保留、推理有效性及说明。复核历史只追加，并使用版本号避免多人覆盖。AI 复核和人类复核分开；姓名与独立性是声明，本机界面不认证复核者身份。

“已审子集准确率”仅描述已审样本。“按声明独立复核准确率”要求整批应审题均已完成必要项、题单和来源摘要完整；分母仍为完整冻结题单。分组指标使用冻结题型，普通比较或多轮追问不自动算多跳。富化以预先选定的单个事实为统计单位，参考事实需要独立查原文，不能从系统输出复制生成。小样本同时提供 95% Wilson 区间。此比例及区间是样本统计，不保证总体质量，也不证明独立盲测。

持续观察使用本次选定的 **72 小时发布窗口 + 最多 24 小时迟到核对**。创建时由服务器确定开始时间，不能事后挑选窗口；每 60 秒只读采集库，持久化必要字段、来源运行结果和快照摘要链。电脑休眠或应用退出会停止观察，重启后保留原窗口并显示实际缺口，不补造过去的心跳。采集系统的原有定时任务继续负责联网采集。

延迟 = 首次采集时间 − 原始公开发布时间；分别统计 ≤6、≤12、≤24 小时，并保留未知、负延迟、仅日期、失败和迟到记录。分母采用每来源每条记录，不与按 CVE 去重的统计混用。窗口内已采到记录的及时率不能证明没有漏采：还需导入覆盖整个窗口的上游列表、查询范围、获取时间、正文及摘要，逐项确认 `in_scope`，核对 collected / late / missing / unknown / not_due / excluded。清单的完整性是提交者声明，正文摘要只证明一致性，不证明源站完整或真实性。无清单时召回率和完整时效验收保持空值。

窗口结束后仍等待最后发布的记录达到统计阈值；满足冻结条件后才可生成不可覆盖的最终报告。观察中的导出明确标为进度快照。材料区显示每份文件的实际版本、生成时间、SHA-256，并提供下载；旧版本报告不会因软件升级被改标成新版本。

验收数据独立保存在 `MAIN_DATA_DIR/acceptance.sqlite3`，材料保存在 `MAIN_DATA_DIR/acceptance-evidence/`。应连同原始采集库备份。`ACCEPTANCE_OBSERVATION_ENABLED=0` 可在测试环境停用观察器；不影响已有记录。

接口入口为 `/api/acceptance/summary`、`/quality`、`/observations`。导入、复核、冻结接受同源 JSON；下载只允许已登记材料 ID，不能从网页读取任意文件。部署人员可用 `python scripts/register_acceptance_materials.py --help` 登记明确的交付文件，数据库、配置和密钥不属于可下载材料。

## 固定观察期

先记录待评测 commit、配置、运行地点、持续运行方式、来源名单，以及固定的开始与结束时刻。运行前确定窗口，不能在看到超时之后重新挑选开始时间。建议至少覆盖工作日和周末；观察长度由团队提前约定，并非赛题强制天数。

固定窗口按**公开发布时间**选择 `[start, end)` 样本；`as-of` 是冻结查询截止时刻，必须晚于或等于 `end`。窗口最后发布的信息应有充分的后续观察时间，再冻结报告；后续才采集到的记录仍纳入该发布窗口并保留实际延迟。

例如，团队可以提前约定北京时间 2026-10-11 08:00 至 2026-10-18 08:00，对应下面 UTC 参数；`as-of` 晚六小时，属于示例而非已完成的观测。应在对应时间到达后生成报告，不得使用未来时间声称已有结果。

```bash
python scripts/evaluate_observation.py \
  --db /path/to/intelligence.db \
  --start 2026-10-11T00:00:00Z \
  --end 2026-10-18T00:00:00Z \
  --as-of 2026-10-18T06:00:00Z \
  --output data/evaluation/observation-20261018.json
```

数据库必须真实存在。请在 `as-of` 对应时刻保存一致的 SQLite 快照，并针对该快照生成报告；当前数据库不能还原任意过去时刻的全部载荷版本。脚本使用 SQLite `mode=ro`、`query_only` 和单次读事务，既不调用采集器或模型，也不更改 `first_seen_at`、分类、游标、监测基线或数据库表。报告文件使用独占创建，已有报告不会被覆盖。保留修复前报告，修复后的报告另存文件。`as_of_elapsed=false` 表示还未到达冻结时刻，不能当作完整观察期证据。

报告分别展示：

- `source_items`：每源每条记录首次入库；重复 CVE 在不同来源具有独立样本。
- `knowledge_documents`：非 CVE 文档的公开发布与首次入库。
- `unified_vulnerabilities`：融合后按 CVE 去重，采用已记录的原始发布时间来源。
- `strict_under_6h` / `strict_breaches_ge_6h`：用户要求的严格 **小于六小时**。
- `contest_within_6h` / `contest_breaches_gt_6h`：赛题文字的 **不超过六小时**。恰好六小时在两个口径下结论不同。
- `historical_backfill` 与 `historical_breaches`：窗口之前发布的历史资料及原有超时逐条另列，不删除或重置。
- `excluded`：只有日期、未知时间、负延迟、截止后时间、无效载荷和 CISA KEV 收录日期等不能证明小时级时效的记录。

NVD 有文档约定的无时区时间按 UTC 解析；其他来源必须有明确时区。CISA 的 `dateAdded` 是目录收录日期，不等于漏洞首次公开时间。缺少有效时间的记录不是达标样本。

数据库只能显示已采集数据，不能自动发现尚未采集、被分类排除或源站漏返回的数据。因此 `sla_verified` 固定为 `null`；持续在线性需另看实际任务日志，漏采率需另冻结上游列表并逐条核对。端到端“采集后多久可问答”还需检查 A/C 的同步、队列与索引记录。

## 独立人工标注

由没有参与对应模块开发的人提前选取正例、负例、边界例和新发布数据，冻结完整题单与来源快照，保留文件哈希。不能从系统输出反向生成标准答案，不能只标注回答正确或成功处理的条目。三人团队可交叉标注、交叉复核，记录实际关系；这种声明本身不能证明完全独立盲测。

标签格式如下。**此模板没有分数**；把 `null` 替换为人工判断或真实测量，删除示例 ID 并使用真实冻结样本 ID。未出现的模块和未完成标注的模块指标仍为 `null`。

```json
{
  "schema_version": 1,
  "metadata": {
    "commit_sha": "填写完整提交 SHA",
    "dataset_id": "填写冻结数据集名称",
    "reviewers": ["填写标注者", "填写复核者"],
    "development_unseen": null,
    "notes": "记录来源、抽样方法、测量环境和标注者与开发者关系"
  },
  "classification": [
    {"id": "替换为真实样本", "expected": null, "predicted": null}
  ],
  "enrichment": [
    {"id": "替换为真实样本", "expected_facts": null, "predicted_facts": null}
  ],
  "qa": [
    {"id": "替换为真实问题", "correct": null, "citations_supported": null,
     "latency_seconds": null, "used_model": null}
  ]
}
```

`classification` 使用真正的布尔值，不接受字符串 `"true"`。`expected` 是人工 AI 安全范围标签，`predicted` 是冻结时系统输出；未处理或待复核不能伪装成已正确分类。

`enrichment` 先由人工规定规范化事实表达，例如 `cvss.version=3.1`、`cvss.score=9.8`、`affected.product=ollama` 和版本边界，再独立提取系统输出。`expected_facts`、`predicted_facts` 是字符串列表，按集合匹配，生成事实级 TP/FP/FN、微平均 precision/recall 和完整记录精确匹配率。事实格式、字段粒度和哪些记录属于该维度必须提前确定；集合相等不是自动语义判断，也不能将不同的业务口径直接称作赛题官方成绩。

`qa.correct` 与 `citations_supported` 由人工看完整回答和来源判断。`latency_seconds` 测量真实部署从发起 HTTP 请求至收到完整响应的时间，包括检索、模型、核对、异常回退；不要用首 token 时间代替完整响应。保留模型实际采用／回退状态 `used_model`、并发条件和冷启动情况。

```bash
python scripts/evaluate_observation.py \
  --db /path/to/intelligence.db \
  --start 2026-10-11T00:00:00Z \
  --end 2026-10-18T00:00:00Z \
  --as-of 2026-10-18T06:00:00Z \
  --labels /path/to/frozen-human-labels.json \
  --output data/evaluation/observation-and-quality-20261018.json
```

未全部标注时只显示已评分数量和计数，完整数据集的质量指标保持 `null`，避免通过挑选已复核条目夸大准确率。分母为零的 precision/recall 也为 `null`。问答时延有独立测量数量，缺少任何题目计时就不会声称全体满足五秒要求。脚本记录标签哈希与人工元数据声明，不自行认证“独立”。

决赛富化最高档是准确率和召回率均至少 95%；问答达标档含准确率至少 75% 与响应不超过五秒，最高档还要求至少 95% 准确率和可解释推理链。初赛和决赛的指标不同，最终汇报应写清实际业务口径、样本量、来源和限制。

## 自动功能检查

新增 `.github/workflows/system-checks.yml` 对 PR、main/dev 提交和手动启动执行 A/C 与 B 的独立依赖环境测试、SQLite 时效边界测试，检查演示、持续采集和 Actions 镜像三份独立 Compose 配置，并实际构建演示容器、验证 B API 到 C 的资料同步。不注入付费模型 Secret，分类模型调用预算设为零，关闭自动采集后台；离线测试入口阻止主测试进程的公网 socket，仍允许本地 HTTP 测试服务。容器集成使用合成种子、独立 CI 卷和内部网络，运行服务无法访问公网；结束只清理该 CI 任务生成的容器和卷。

本地使用与 CI 相同的命令（A/C 与 B 已共用核心锁文件，可以使用同一虚拟环境；两组测试仍从各自工作目录启动）：

```bash
python scripts/run_offline_tests.py --start-directory questions
python scripts/run_offline_tests.py --start-directory scripts/tests
cd intelligence
python ../scripts/run_offline_tests.py --start-directory tests
```

CI 通过表示开发行为检查通过，不等于已运行固定观察期，不等于真实来源全部可用，也不等于独立样本已达到赛题评分阈值。
