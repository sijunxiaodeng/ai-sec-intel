# 问答能力现状与独立计分

赛题九原文中，初赛基础问答准确率 ≥70% 为合格，含推理链的深度问答为良好，多跳准确率 ≥85% 为优秀。决赛准确率 ≥75% 且响应 ≤5s 为合格，准确率 ≥90% 且支持多跳为良好，准确率 ≥95% 且推理链可解释为优秀。这些成绩需要评测证据；技术组件名称和回归测试数量不能直接换算为比赛分数。

## 当前能力与缺口

| 检查项 | 当前证据 | 尚未完成的部分 |
| --- | --- | --- |
| 中文嵌入、混合检索 | `rag/hybrid.py` 实现 BAAI/bge-small-zh-v1.5、BM25、RRF；`rag/library.py` 对资料复用同一索引机制 | 本机模型和索引须显式准备。缺模型时实际使用 BM25。没有独立测量检索召回率。 |
| 分块和索引一致性 | `rag/evidence.py`、`rag/ingest.py` 保存原文片段、来源定位；变更时检查摘要并更新索引 | 没有经过盲测比较的分块参数。 |
| 重排序 | 目前使用词法/向量排名融合 | 没有 cross-encoder reranker；不能把 RRF 称为 rerank 模型。 |
| 意图和结构化回答 | `agents/question_scope.py`、`agents/qa_agent.py`、`rag/answer.py` 按评分、版本、条件、影响、修复、PoC 和资产主题组织回答 | 主题识别主要依赖规则，未证明开放问题的语义意图识别。 |
| 多轮和澄清 | `agents/conversation.py` 可解析明确 CVE、有限产品/漏洞指代和主题追问；范围不明时请求编号 | 会话在进程内，重启丢失；资料问答未复用漏洞会话，复杂省略和跨进程会话仍缺。 |
| 溯源和拒答 | `agents/citation_guard.py`、`agents/verifier_agent.py` 检查字段与引用；失败后回退摘录。无对应证据和具体资产条件时拒绝断言 | 程序规则不能证明所有语义引用支持关系。 |
| 跨文档和解释 | `agents/relations_qa.py` 提供来源绑定的主题路径；`agents/general_reasoning.py` 提供可选问题分解、补充检索、引用验证、结论核对和过程记录 | 固定主题路径不是任意多跳；通用推理依赖实际配置的模型。`semantic_accuracy_measured` 仍为 false。 |
| 题单和准确率 | `questions/qa_evaluation.json` 有 36 道漏洞开发题，`questions/relations_evaluation_v2.json` 有 23 道跨文档开发题 | 合计 59 个开发题目不等于 59 道独立盲测。尚无完整独立人工复核准确率，也未按多跳题型统一标注。 |
| 响应耗时 | `questions/evaluate.py` 计时完整 TestClient 返回；`questions/evaluate_relations.py` 计时完整本机 HTTP 返回 | TestClient 不能充当真实网络耗时。尚无代表性线上模型、外网、并发和冷启动的 ≤5s 结论。 |

`questions/results/qwen_local_baseline.json` 是历史公开 36 题结果：自动规则通过 24 题，实际采用模型 14 题，采用模型且自动检查通过 2 题，人工准确率为空。该记录说明仍需测量和改进，不代表当前模型，也不能按 24/36 宣称语义准确率。

## 本轮补充

漏洞题单 runner 支持 `--dataset`，因此独立评测者可以冻结自己的题目、来源前提和复核要点，无需替换公开开发题单。报告记录实际所选题单摘要、完整题数和逐题人工表。

```bash
.venv/bin/python -m questions.evaluate --dataset /tmp/frozen-qa.json --db /tmp/frozen-qa.sqlite3 --prepare --output /tmp/qa-report.json
.venv/bin/python -m questions.evaluate_relations --dataset /tmp/frozen-relations.json --mode rules --output /tmp/relations-report.json
```

`--prepare` 会联网获取并校验所列来源，不会自动生成正确答案。更换题目必须在运行前完成，不能看到结果后删除失败题。使用模型时分别添加 `--mode model` 并保留实际采用/回退字段。

新工具 `questions/scorecard.py` 合并同一模式的完整报告，对题号、冻结摘要、来源响应摘要、题数及耗时做校验。每题还需由未参与实现的人声明身份和独立性。漏洞报告人工字段示例：

```json
{
  "correct": false,
  "citations_supported": true,
  "reviewer": "team-reviewer-02",
  "independent_human": true,
  "reasoning_kind": "multi_hop",
  "reasoning_explained": false,
  "notes": "写明判断依据和错误位置"
}
```

跨文档报告继续填写 `source_supported`、`relevant`、`conditions_preserved`、`synthesis_correct` 四项；同时填写上述身份、独立性和题型字段。题型可取 `single_fact`、`comparison`、`multi_hop`、`refusal`、`multi_turn`、`other`。多文档引用本身不能证明多跳，须检查答案是否完成需要的中间关联，并保留依据和限定。

```bash
.venv/bin/python -m questions.scorecard /tmp/qa-report.json /tmp/relations-report.json --output /tmp/qa-scorecard.json
```

任一题缺独立人工复核，或运行仅选择题单子集、缺冻结/来源摘要，完整 `independent_accuracy` 均保持为空。`reviewed_subset_accuracy` 仅用于定位已复核子集的问题；不能作为整套达标成绩。重复题不能重复计数，rules/model 不允许混合汇总，实际采用模型的结果另列。原有旧报告若缺新增元数据，须重新完整运行，而不能只补字段伪造测量。

工具还按人工标注的题型分别计算准确率和解释比例，分别记录 TestClient 与真实本机 HTTP 的耗时；自动规则通过数仍作为工程诊断。`competition_passed` 始终为空，程序不自动授予比赛分数。

程序只能校验声明，不能证明复核者身份、独立性或样本代表性。下一步仍需团队安排独立人员编写并冻结代表性题单，实际使用待参赛模型运行、逐题复核和记录线上端到端延迟；公开题单接受独立人审后仍不是盲测题单。
