# 初赛验收与交付

本页用于当前 main 收尾。依据赛题九初赛材料与评分要求，不把决赛匿名模板、五秒响应或决赛召回率门槛追加为初赛硬要求。系统实现、离线工程测试、真实运行、人工质量结论分别记录。

## 提交材料

| 初赛材料 | 必须包含/格式 | 当前收尾动作 |
|---|---|---|
| 技术报告 | Word与PDF各一份；总体架构、Agent方案、监测/富化/问答详细设计、技术选型、流程图、实现/核心代码、效果、性能分析、创新点 | 已生成本机报告，交付目录保留源文件、PDF及版式核验记录；提交前核对最终版本和文件摘要 |
| 操作演示视频 | 展示实际系统操作；赛题未指定时长 | 已生成基于真实界面截图的分段操作导览，明确标注其不是连续录屏；[全系统演示脚本](../验收包/演示脚本.md)可用于现场连续演示 |
| 技术讲解PPT | 以PDF格式提交 | 已生成可编辑PPTX与讲解PDF；与最终报告保持版本和指标一致 |

源码由企业在参赛平台审阅，按比赛安排提供当前版本；不把另交源码压缩包列为强制要求。建议的亮点预览页不是硬性格式。正式材料不能包含密钥、真实资产地址或不必要的个人信息。

架构素材：[智能体编排与工具轨迹](智能体编排与工具轨迹.md)有当前研判反馈流程；[仓库文件与运行说明](仓库文件与运行说明.md)保留历史架构与逐文件说明。报告优先采用当前流程和明确版本的图，不把旧文件数/测试数作为当前成绩。

## 三类证据

| 标记 | 含义 | 可以说明 | 不能说明 |
|---|---|---|---|
| `offline_fixture` | 临时合成输入、真实本机HTTP和SQLite；外部提供者受控替代 | API、持久队列、真实调查循环、证据归档、风险与引用问答的连接及变更失效 | 真实源可用率、模型质量、采集时效、互联网资产发现或准确率 |
| `live_capture` | 从当前已启动服务采集现状；`--ask`才显式请求一次问答 | 所选CVE/资产的job、run、版本/来源/风险/引用绑定和HTTP耗时 | 全库完成率、全部来源健康、全量索引、语义正确性、持续SLA |
| `waiting` | 材料/任务/引用尚未满足，或没有显式请求问答 | 告知仍需补什么，保留未知 | 不能填0冒充没有问题，也不能改写为通过 |

现有 CI 已有主/B测试、Windows脚本/兼容与容器导入检查；每次发布仍查看对应提交的实际Actions结果。自动测试通过率不等于比赛准确率。

## 一条CVE的可复现链路

先按[部署与联调](../验收包/部署与联调.md)启动。真实场景选择已收录CVE并登记授权组件；正常后台或主动研究创建调查，等待工具执行。不要为了验收给真实库导入虚构“生产资产”。

离线验证命令：

```powershell
python scripts/run_offline_tests.py --start-directory scripts/tests --pattern test_acceptance_snapshot.py
```

独立子进程内使用 `CVE-2099-90099` 合成数据和临时目录，外网被禁止。真实调查循环调用受控来源，实际存档NVD格式证据并执行确定性CPE/版本评估；经真实API核对风险及问答引用，再检查升级重评、unknown拒绝解决、来源修订/撤回失效。未调用模型、未准备语义向量；测试没有生成真实准确率。

只检查已有真实状态：

```powershell
python scripts/acceptance_snapshot.py --cve CVE-2024-37032 --output data/acceptance/status-01.json
```

显式提问并检查完整绑定：

```powershell
python scripts/acceptance_snapshot.py --cve CVE-2024-37032 --asset-id YOUR_REGISTERED_ASSET_ID --ask --output data/acceptance/chain-01.json
```

替换CVE和资产编号为本次验收对象。`--ask`使用服务器当前模型配置，可能产生模型费用并写问答记录；没有该开关不会请求模型。脚本不触发采集、导入、重试、研判或处置；GET风险接口可能校正派生旧结论，不能称为字节不变的数据库取证。仅访问本机，不跟随重定向，异常只输出类别，报告不导出完整答案或资产地址。

可加 `--commit 完整40位SHA` 记录运行者声明；当前服务没有提供可信服务端Git版本证明，因此报告保留 `commit_verified_by_server=false`，不认证填写值。输出文件必须是新路径。退出码0表示所选链路绑定通过；1为请求错误；2为等待材料或没有请求问答。它们不等同比赛合格/不合格。

检查绑定包括：当前CVE评估有来源摘要和引用；风险未失效；风险run_id与持久任务/运行匹配；任务修订与风险source_revision一致；工具调用与停止原因存在；回答引用和风险版本引用指向同一来源摘要；查询前后风险指纹/run/来源摘要稳定。HTTP多请求不是原子快照。未知影响不能解决、论文缺口等仍可保留，不为了报告通过补造事实。

当前API不提供全部CVE索引队列的精确完成证明，`semantic_index_verified=null`；准备模型后分别核对两库实际查询模式，不凭数据库文件存在或全局done数量判定索引完成。若无资产，只能验证研究任务，资产风险链保持waiting，这不是公共监测必须先输入资产。

## 性能与质量

初赛指标按原文区分：来源类别覆盖；至少三种/五种以上富化维度及关联推理；基础、深度及多跳问答；发布至采集≤24/12/6小时；富化准确率≥70/85/95%；基础问答≥70%、优秀多跳≥85%。来源类别不是URL数量；有字段不是该字段准确。

- 真实时效：提前固定观察窗口、冻结截止与数据库，使用 `scripts/evaluate_observation.py`。保留未知时间、失败、partial、历史补采和超限；不得只选已及时采集样本。已入库数据无法自行证明漏采率，需上游列表核对。赛题未规定必须观察七天。
- 富化：提前冻结样本、事实粒度与参考来源，人工核对预测事实。CVSS、版本、论文、资产、PoC等维度分别说明可验证范围，不能用字段非空率当准确率。
- 问答：用 `questions/evaluate.py --dataset ...`、`questions/evaluate_relations.py --dataset ...` 或 `questions/acceptance_round.py` 捕获实际回答；人工核对事实、引用支持、限定条件和多跳中间关联，再使用 `questions/scorecard.py` 汇总。模型采用/回退与规则答案分别记录，完整HTTP耗时与TestClient耗时分开。

旧 `questions/acceptance_round*.json` 冻结的是旧代码和来源，当前改动后应新建批次；摘要校验拒绝旧题单是正常保护，不能直接删除检查或覆写旧结果。开发题可以用于回归，但不得冒称未见独立题。人工独立性是可靠性方法，程序只能记录声明；赛题没有指定必须某类身份或固定题数。

## 收尾清单

1. 冻结发布commit、实际运行模式、资料与模型配置；完成隔离整链回归和对应CI。
2. 选择真实案例，保存任务/工具/来源/风险/问答报告；准备语义检索和模型时如实记录实际模式。
3. 冻结评测题单与来源，完整保留失败和人工复核；持续保存真实采集时效，不提前填写准确率。
4. 编写并导出技术报告Word/PDF、讲解稿PDF，录制全系统操作视频；打开检查版式、图表、版本和数字一致。

## 2026-10-15 问答质量修复

此次修复针对真实开发题复核暴露的问题：SSVC 的 `none` 不再扩写成“不存在可利用路径”，`partial` 不再自行解释成具体功能损坏；NVD 的 `Exploit`、`Patch` 标签仅输出候选来源事实，不推断代码可用性或修复效果。未抓到补丁正文时仍保留带来源的候选链接，并在详情与修复问答中展示。

未知但明确指定的 CVE 会成为后续追问范围，不退回旧漏洞；宽泛风险比较同时覆盖已有评分、版本、条件和技术影响，并保留资产暴露及业务条件未确定的边界。缺少 CVSS 不再跳过版本、补丁和 PoC 检查。

跨文档推理采用完整原句的相关性排序，最多16个选项、3200字符，保留来源轮转和摘要范围。每条候选结论单独核对支持、范围及反证；普通资料差异不会连带否决同段落的全部结论。原句匹配和模型复核仍不等于语义正确，多跳质量需要另行评估。

本机主系统离线回归：871项、865通过、6跳过。36题公开开发集与本地模型对比结果单独存档，保留自动措辞检查失败、模型回退和审查者身份；不得将其自动通过率写成独立准确率。技术报告的时效统计也只表示实际观测窗口，不承诺未观测来源全部及时。

真实资产平台发现、PoC隔离可用性实验、通用资料完整多轮和跨进程会话仍是功能/实证边界。不要把添加特定框架、reranker或指定商业平台当作初赛完成的必经前置；优先补当前可展示链路和实测结果。
