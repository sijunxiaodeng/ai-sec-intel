# 任务 C 部署与联调

以下步骤用于 Windows PowerShell 的新环境准备和队友联调。当前系统已在开发电脑上运行；另一台电脑的干净部署尚未实测。仓库不携带本机数据库、模型缓存、候选审核历史或密钥，因此拉取源码后需要重新准备资料。

## 安装与启动

使用 Python 3.10 或以上，开发电脑为 Python 3.12。准备 Git 后在目标工作目录执行：

```powershell
git clone --branch dev https://github.com/sijunxiaodeng/ai-sec-intel.git
cd ai-sec-intel
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-rag.txt -r requirements-test.txt
.venv\Scripts\python.exe -m unittest discover -s questions -p 'test_*.py'
.venv\Scripts\python.exe -m rag.prepare
.venv\Scripts\python.exe main.py
```

私有仓库访问使用队友已有的 GitHub 授权。直接使用虚拟环境的 Python，不必修改 PowerShell 执行策略。网页地址为 `http://127.0.0.1:8023`；若端口被占用，先确认现有进程用途，不直接停止未知进程。

`rag.prepare` 加载人工整理的历史样例，不联网采集、不下载嵌入模型。服务器启动会启用 6 小时后台任务；启动时不立即采集，但持续运行后可能联网更新。开发演示和实时监测的时间记录应分别保存。

## 准备语义索引和公开资料

在第二个 PowerShell 窗口进入同一仓库目录。需要语义检索时，显式准备本地 BGE 模型：

```powershell
.venv\Scripts\python.exe -m rag.prepare --semantic
.venv\Scripts\python.exe -m rag.ingest --cve CVE-2024-37032
.venv\Scripts\python.exe -m rag.library --sync
```

首次模型准备会下载文件；详情见 [rag 说明](../rag/README.md)。无法下载时，保留 BM25 基线，不把它标为语义检索已就绪。模型准备不需要聊天 API Key。

资料同步会访问已配置公告、博客、arXiv、固定官方标准/政策及历史起始链接，限流/访问失败时记录状态。新增漏洞通过「情报监测」采集后再处理关联资料；样例不能冒充新发现记录。

在「安全资料库」找到间接提示注入论文的摘要，点击「获取论文全文」。论文题名为 `Not what you've signed up for: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection`。全文与摘要是独立记录；要演示该主题关系，必须有已核对版本的 HTML 全文与 NIST PDF。模型供应链主题需要 HF Pickle 文档和 NIST PDF。

已准备模型时，同步/入库会尝试增量更新索引。若资料先入库而向量模型之后才准备，可显式重建资料库索引：

```powershell
.venv\Scripts\python.exe -c "from rag.library import LIBRARY_DB; from rag.hybrid import build_index; print(build_index(LIBRARY_DB))"
```

该命令为显式索引准备，可能初始化模型缓存；普通检索和问答不会自动下载模型。检索结果中的 `mode=hybrid` 才表示本次成功用了混合检索，索引文件存在不等于索引可用。

关系注册文件绑定实际版本和片段摘要。新机器抓到的官网正文若已变化，关系可能为 partial/empty；需核对新原文并更新注册关系，不能沿用旧中文结论强行展示。同步成功也不能自动保证题单来源前提未变。

## 配置问答模型

规则摘录与限定综合可在不配置聊天模型时运行。需要真实模型回答时，在「模型设置」填写已有兼容接口，检查连接，并保留采用/回退状态。只在本机保存 Key，不复制开发电脑的 `config/local.json` 到仓库或报告。

当前两类资料分析中的模型只做路径选择，候选提取中的模型只选择原文句子和分类。漏洞问答是另一条带字段和引用守卫的路径；演示与报告中需区分其作用。

## 验收和联调

```powershell
.venv\Scripts\python.exe -m questions.acceptance_snapshot
.venv\Scripts\python.exe -m questions.evaluate_relations --dataset questions/relations_evaluation_v2.json --mode rules --output data/relations-v2-rules.json
```

快照先检查当前资料、两个主题的关系及引用绑定。源文版本不满足题单前提时，开发评测程序会停止并提示复核，不能把更换正文后的旧答案当标准答案。使用 `--mode model` 会实际调用已配置模型，应在模型模式的独立运行报告中记录采用与回退。

| 联调对象 | 入口 | 通过条件 |
| --- | --- | --- |
| 统一富化结构 | `enrichment.service.enrich(item)` | 返回 `item/cvss/epss/kev/poc/papers/references`，缺失值明确，字段兼容现有结构 |
| 知识库 | `rag.evidence.save/search_evidence`、资料库接口 | 记录可重复入库、来源可追溯；资料库与 CVE 库分开 |
| 公开源补充 | 「查询 EPSS、KEV 与论文」及关联资料操作 | 失败项有状态、其他模块可继续；缺字段不编造 |
| 多轮问答 | `POST /api/ask`、情报问答 | 先有编号再追问，切换编号与新会话无旧证据串用；关键断言有有效来源 |
| 关系分析 | `POST /api/library/analyze` | 两个来源和全部固定前提满足，缺证据不形成结论；通过候选单独展示 |
| 候选审核 | `/api/library/relations/candidates` | 待审核隔离、审核留痕、撤销有效，来源变化停用旧结果 |
| 工程与演示 | 本机快照、固定演示脚本 | 干净部署记录、三次演练及失败处理记录齐全，不用开发测试结果代替正式质量指标 |

联调记录至少保留：Git 提交号、Python 与依赖版本、操作系统、运行日期、数据来源/版本、检索模式、模型采用/回退、接口耗时和失败项。原始网页、报告草稿和本机运行数据放 `data/`，提交材料用脱敏结果。

## 当前部署边界

当前监听本机地址，没有新增远程访问、账户权限或公网发布。本包不提供 Docker/CI/CD，也没有宣称容器化验收通过。需要多机共享、容器化或监控告警时，在第三阶段明确部署目标并实际测试。
