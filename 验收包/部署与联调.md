# 全系统部署与联调

本页按当前 main 说明启动和验收。历史双环境联调记录仍保留在 [干净部署与团队联调记录](干净部署与团队联调记录.md)，不作为当前安装步骤。主应用和 B 共用 `intelligence/requirements.lock.txt` 核心依赖，不再需要因 FastAPI/Pydantic 版本差异拆成两个 Python 环境。

## 获取源码和隔离演示

建议使用 Python 3.12；发布验收时记录实际完整 commit。Windows PowerShell：

```powershell
git clone --branch main https://github.com/sijunxiaodeng/ai-sec-intel.git
cd ai-sec-intel
git rev-parse HEAD
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe scripts/offline_demo.py
```

打开 `http://127.0.0.1:8023`。离线演示使用独立 `.demo/offline/`，明确标注合成记录；不调用真实来源或模型，也关闭自动处理。它验证产品入口和导入链，不是实时情报、模型质量或时效成绩。

也可使用 `docker compose -f docker-compose.offline.yml up --build -d`，无需本机 Python；详见 [DEPLOY.md](../DEPLOY.md)。端口冲突时先核对已有进程，不覆盖真实数据或停止未知进程。

## 运行真实情报

退出隔离演示后，在上述虚拟环境运行：

```powershell
.venv\Scripts\python.exe main.py
```

原生默认 `embed`：B 查询嵌入，真实采集在隔离子进程运行，产品入口仍为 8023；启动后后台采集一轮，每轮结束后默认等待 15 分钟。一般资料同步另有 6 小时间隔。正式模式不会自动灌入历史样例。实际失败、partial、历史窗口积压和未知计数应保留，轮询间隔不等于发布至入库时效。

若仅检查已有库，可以在本次终端启动前设置下列环境变量；这会暂停本次进程的自动采集和自动处理，之后需要移除变量再启动才能恢复：

```powershell
$env:AUTO_MONITOR_ENABLED='0'
$env:AUTO_MONITOR_ON_START='0'
$env:AUTO_INGEST_ON_COLLECT='0'
.venv\Scripts\python.exe main.py
```

容器正式模式二选一：持续采集用 `bash scripts/production-up.sh collector`；Actions 快照消费用 Windows `scripts/production-up.ps1 -Sync` 或 `bash scripts/production-up.sh actions`。准确配置、持久卷、只读令牌与启动检查见 [正式数据部署与交付](../docs/正式数据部署与交付.md) 和 [Docker Desktop部署闭环](../docs/Docker%20Desktop部署闭环.md)。不要同时运行多个占用 8023 的模式，不对真实卷执行删除卷命令。

Windows 真快照导入已保存证据；该记录仅证明交付与两路持久消费，不证明当前后台任务完成或无人值守 SLA。源码不包含个人模型配置、运行库、完整原文及模型缓存，换环境仍需准备这些数据。

## 证据、索引和模型

网页收录情报后可抓取关联资料；正式模式后台按持久任务逐批处理，失败退避重试。`/api/processing/status` 区分 pending、running、retry、failed 和 deferred。索引 deferred 时 BM25 可用，但不能宣称已启用语义检索。

准备已有正式证据库的语义检索：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-rag.txt
.venv\Scripts\python.exe -m rag.prepare --semantic --db data/task_c.sqlite3
.venv\Scripts\python.exe -m rag.prepare --semantic --db data/library.sqlite3
```

先有真实证据再建索引；`MAIN_DATA_DIR` 自定义时修改数据库路径。首次准备可能下载 BGE 模型，离线本地模型参数与容器 `INSTALL_SEMANTIC=1` 见 [rag/README.md](../rag/README.md)。安装依赖不等于模型/索引就绪。普通 `python -m rag.prepare` **不导入样例、不下载模型**；单独演示历史样例须显式使用 `--demo`，不要把它用于正式库。

在“模型设置”配置兼容接口并测试，再用真实问答保留模型采用/回退状态。默认研判使用规则规划；`INVESTIGATION_USE_MODEL=1` 才启用受约束 LLM 工具选择。漏洞问答、固定主题关系路径、通用资料推理、调查工具选择的模型作用不同，详见 [智能体编排与工具轨迹](../docs/智能体编排与工具轨迹.md)。密钥不进入仓库或报告。

## 复现与验收

工程回归使用 CI 同一离线入口：

```powershell
.venv\Scripts\python.exe scripts/run_offline_tests.py --start-directory questions
.venv\Scripts\python.exe scripts/run_offline_tests.py --start-directory scripts/tests
Push-Location intelligence
..\.venv\Scripts\python.exe ../scripts/run_offline_tests.py --start-directory tests
Pop-Location
```

仅复现同一 CVE 的调查→证据→风险→问答与变更失效：

```powershell
.venv\Scripts\python.exe scripts/run_offline_tests.py --start-directory scripts/tests --pattern test_acceptance_snapshot.py
```

此测试使用临时数据库、真实回环 HTTP 和 SQLite；替代外部来源输入，不替代调查/版本评估/风险/问答业务逻辑，不访问公网或模型。不得据此填写真实准确率。

真实环境的可选报告：

```powershell
.venv\Scripts\python.exe scripts/acceptance_snapshot.py --cve CVE-2024-37032 --output data/acceptance/status-01.json
.venv\Scripts\python.exe scripts/acceptance_snapshot.py --cve CVE-2024-37032 --asset-id YOUR_REGISTERED_ASSET_ID --ask --output data/acceptance/chain-01.json
```

第一条不请求采集、研判或模型，缺资产/任务时记录 waiting；第二条的资产编号需替换为已登记真实编号，`--ask` 明确发起一次版本问答，可能调用当前配置的付费模型。不会自动导入资产、重排任务或修改处置。普通 GET 可校正旧的派生风险状态，问答会保存会话/运行历史。报告不覆盖已存在文件。

报告保留同一 CVE 的任务修订、run_id、来源摘要、风险指纹、引用交集与前后稳定性；完整答案和资产地址不导出。`chain_bindings_verified` 只表示选定链路绑定通过，准确率、SLA、语义索引状态与比赛达标不由此判定。退出码 0 表示链路绑定通过，1 为请求失败，2 为等待证据/未请求问答。

旧 `python -m questions.acceptance_snapshot` 仍用于两个固定主题的资料快照；旧冻结题单与当前代码不一致时应新建评测批次，不能绕过摘要检查。完整交付清单、性能口径和人审流程见 [初赛验收与交付](../docs/初赛验收与交付.md)。
