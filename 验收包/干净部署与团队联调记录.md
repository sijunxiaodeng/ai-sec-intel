## 实际启动与三次演练

先执行 `rag.prepare`，载入 8 段人工整理的历史证据，再通过未经替代的 `api.app:app` 启动服务。无聊天密钥时，历史漏洞版本问题返回两条引用，核对通过；资料库为 0 份，说明源码不会自动携带开发资料。安装 fastembed 包不等于已下载嵌入模型，此次没有准备语义索引。

随后用 [演练程序](../questions/rehearse_team_chain.py) 在三份独立源码副本中，运行队友 SQLite 入库、融合 CLI、无模型规则分类和只读 API。根目录采集器实际读取队友 HTTP，再经过富化、知识库写入、关联证据存档及 `/api/ask` 问答。为隔离外部服务，只有外部监测/抓取响应被替代，业务步骤没有跳过。

输入明确为合成 `CVE-2026-10001`，CVSS 来源写作 `synthetic-fixture`，不代表真实 NVD 漏洞。NVD/OSV 监测故意失败、关联 NVD JSON 返回合成响应、外部参考页故意超时；三轮都保留失败状态并继续处理队友来源。仅在演练副本清空历史演示卡片，正式开发目录未写入这条合成记录。

| 核对对象 | 实际结果 |
| --- | --- |
| 两服务依赖与 HTTP 连接 | 独立环境运行，队友数据库健康检查通过 |
| 采集→富化→入库 | 每轮获得 1 条合成记录；评分、向量和来源保留 |
| 连续追问与字段范围 | 第一轮评分，第二轮只问版本；继续沿用编号，不再附评分 |

| 会话隔离 | 新会话无编号时要求明确对象；切换未知编号不沿用原漏洞证据 |
| 重复采集 | 记录仍为 1 条，片段标识前后相同 |
| 缺模型与索引 | 模型请求 0 次，检索为 BM25，未准备向量模型 |
| 来源异常 | 监测失败步骤和参考页错误均保留，成功证据可回答 |

每轮 18 项检查、6 次业务 HTTP 请求；三轮问答请求耗时约 11–48 毫秒。它们是同机、顺序、离线合成数据的耗时，不是并发、真实模型或比赛性能指标。正式演示脚本中关系分析、政策全文、候选复核等环节没有计入这三轮。

## 首次失败与修复

首次运行独立服务 192 项测试，其中 28 项在 Windows 临时目录清理时发生 `WinError 32`。原因是测试里的 `with sqlite3.connect(...)` 管理事务但不关闭连接。为 7 个测试文件中的 17 处连接补充 `closing`，仍执行原事务提交/回滚；没有删除或放宽断言，也没有改生产存储逻辑。原样重跑后 192 项全部通过。

第一批三轮联调在「那受影响的版本范围是什么？不要比较评分。」失败：字段排除指令只识别逗号、句号等分句起点，问号后“不要比较评分”没有被裁剪。修复 `agents/question_scope.py`，增加中文/英文问号、感叹号和换行边界；同时测试“不要遗漏”与事实否定仍被保留。主系统由 249 增至 251 项测试并全部通过。

第二批演练的业务接口已通过，但工具自身检查调用 `_all_evidence` 漏传数据库参数，未计成功。修正工具后增加重复采集前后片段标识及存档哈希核对，第三批三轮完整通过。前两批结果保留，不覆盖失败记录。

本机原始结果在 `data/deployment-step20/`；干净检出内的 `data/rehearsal-step20-first`、`data/rehearsal-step20-final` 与 `data/rehearsal-step20-verified` 分别记录三批演练。源码、日志和本机运行状态不整体提交，仓库保留工具、文档及脱敏统计。运行方法见 [部署与联调](部署与联调.md)。
