# 第二十一步：团队资料接入

队友 `intelligence/` 服务中的论文、博客、标准、政策和厂商公告，现在可以进入主系统「安全资料库」，用于检索和带引用的资料问答。同步读取本机只读 API 的题名、描述和来源信息，明确标注为接口字段存档；获取原文需要另行操作。

## 怎么使用

主系统和队友服务分别使用自己的虚拟环境，安装方法见 [部署与联调](部署与联调.md)。先在队友服务所在电脑的仓库根目录打开 PowerShell：

```powershell
Push-Location intelligence
.venv/Scripts/python.exe run_monitor.py --once
.venv/Scripts/python.exe run_intelligence_api_v6.py
```

第一个命令执行真实联网采集，需检查各来源的成功/失败日志；第二个命令保持运行，默认监听 `127.0.0.1:8765`。若已有真实数据库，可以直接启动 API。不要把 API 部署在另一台电脑后仍使用此处的本机地址；当前适配器只支持两个服务在同一台电脑运行。

另开终端，在仓库根目录启动主系统：

```powershell
.venv/Scripts/python.exe main.py
```

访问 `http://127.0.0.1:8023`，进入「安全资料库」，点击「同步团队资料」。页面每次处理按队友更新时间排列的最新 30 条记录，显示同步状态和窗口外剩余数量。勾选所需资料，输入例如“这些资料如何描述提示注入风险？”，点击「按证据回答」。摘要回答标为“接口字段摘录”，并显示字段定位、来源链接和完整性状态。

博客和厂商公告的接口摘要提供「获取来源原文」按钮；成功后选中独立的原文记录，可检索并提取待审核的新文章关系候选。arXiv 摘要继续使用「获取论文全文」，抓取官方 HTML 全文。原文获取失败时保留原摘要和失败状态；原始网站拒绝访问、正文格式不支持或证据不足时，不显示为原文获取成功。

标准和政策的团队记录仍是描述或目录元数据，不自动变成标准全文或正式条文。主系统原有固定官方政策正文、NIST PDF 框架和国标目录同步入口继续使用。

也可在仓库根目录执行：

```powershell
.venv/Scripts/python.exe -m rag.library --team-sync --max-documents 30
```

数量可设为 1–200。这个参数扩大最新窗口，不能翻到所有更早资料；当前没有全量镜像、历史游标或依据记录缺席自动撤回的机制。CLI 出现部分失败或服务失败时退出码为 1，应阅读结果中每份记录的状态。

## 保存与引用

| 内容 | 保存及使用方式 |
| --- | --- |
| 队友类别 | 安全博客/社区→研究文章；论文→论文；标准→标准；政策→政策；厂商公告→厂商公告 |
| 接口证据 | 保存详情接口返回的实际 JSON 字节和 SHA256，定位为 `team_api.title` 或 `team_api.description` |
| 来源身份 | 保留原网址、队友记录编号、来源类别、发布时间、队友内容更新时间、当前获取时间和接口快照地址 |
| 本机编号 | 队友记录按独立命名空间生成 `DOC-...`，同网址摘要不会覆盖已有全文或固定关系来源 |
| 问答引用 | `DOC-.../LIB-...`；每次使用前核对快照与抽取字段、文本摘要、片段定位和引用身份 |
| 正文另存 | 显式获取的原文有自己的文档编号、原网页快照和 `parent_document_id`，与接口摘要分别保存 |

发布时间未知时保持空值；队友数据库的更新时间和本次获取时间不能替代原文发布时间。未保留 `raw_data`，也不把队友字段中的 CVE 标签直接转为已证实的漏洞事实。正文出现编号时只形成提及关联，不代表该文章证明漏洞或修复效果。

重复同步同一记录保持正文及引用身份稳定；描述改变时替换该记录的旧片段并保存新快照。服务不可达、分页总数变化或出现重复记录时停止本轮导入；单份详情无效时报告部分失败，其他有效记录仍可导入，已有成功存档保留。

团队摘要不参与已核对的技术因果关系、原文候选提取或漏洞修复事实。纯团队摘要问答由程序摘录已保存字段，不调用聊天模型；混合选择全文时，全文部分仍遵循现有模型采用/回退规则。使用摘要识别主题不等于标准符合性、法规适用性或攻击效果验证。

## 接口

| 入口 | 行为 |
| --- | --- |
| 队友 `GET /api/documents?limit=...&offset=...` | 发现最新窗口，单页最多 100 条 |
| 队友 `GET /api/documents/{document_id}` | 获取并保存可引用的详情响应，不请求 `include_raw` |
| 主系统 `POST /api/library/team-sync` | JSON `{"max_documents":30}`；返回 `status/attempted/ok/changed/documents/source/overview`，成功处理时另含索引状态 |
| 主系统 `POST /api/library/{document_id}/full-text` | 对支持的团队博客/厂商公告抓取来源正文，或对 arXiv 摘要抓取 HTML 全文 |
| 主系统资料详情、检索和问答 | 沿用现有 `/api/library`、`/search`、`/{document_id}`、`/ask` |

`status=ok/partial/error` 分别表示本轮记录全部有效、部分记录失败、服务或分页失败。服务失败返回 HTTP 200 及 `status=error`，不是同步成功；已有同步任务冲突为 HTTP 409，参数不合法为 422。
