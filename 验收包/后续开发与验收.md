## 下一项开发

新文章候选已支持显式选择存档资料，验证及范围见 [新文章关系提取说明](../新文章关系提取说明.md)。D01—D04 已完成整改及开发复测，第十九步按问题裁剪字段、直接摘录政策范围/日期，并保留“不要遗漏”表达，详情见 [提问范围裁剪与回归](提问范围裁剪与回归.md)。下一项从干净环境重建并进行团队联调，独立来源核对继续待做。不需要用户预先知道答案，参与开发的模型复核仍不算独立验收。后续扩展继续保留以下行为：

1. 只从已存档、完整性通过的资料选择原文，摘要、目录和全文范围分开。
2. 模型输出关系的主语、关系类型、宾语及其引用/条件时逐项绑定来源；主题相近不能直接成为漏洞事实或攻击因果。
3. 新候选待复核，无法确定的条件保持未知；通过原文关联不自动意味着推理结论成立。
4. 文档更新或撤回后关闭旧关系；新增主题与旧漏洞/旧主题的回归检查均通过。

已完成一个注册来源之外的真实文章案例，实际生成结构化候选，2 条通过开发来源复核；其他项保持待审核。PoC 可用代码、互联网资产定位、标准全文等全队范围缺口另见 [赛题要求对照](赛题要求对照.md)，不能凭任务 C 的阶段完成认定全部赛题完成。

## 独立评测准备

现有 36 道漏洞开发题与 23 道关系开发题可用于回归，不直接充当独立题单。第二阶段先冻结待测版本，再准备不同漏洞/文章、同义表达、缺证据、冲突来源、多轮切换和跨文档问题。对新问题，开发者或模型提供的建议答案也需要核对原文后才能成为标签。

富化评测先约定单位，例如「漏洞 × 富化维度 × 可核对事实」，记录应收录事实、已返回事实和错误/遗漏；不以返回字段的数量充当召回率分母。问答评测按整题及关键断言检查，记录引用存在但结论错误、缺条件及拒答是否适当等情况。

参与开发的模型复核可辅助定位问题，不能记成独立人工验收。人工来源复核也需说明是否参与开发、是否事先看过题单，不能仅凭 `user_source_review` 状态计算独立正确率。

响应时间保留完整 HTTP 逐题数据，区分规则、模型采用和回退，记录设备、索引冷热状态、并发数及采集/更新是否同时进行。初赛与决赛的阈值分开，测量后再作达标判断。

## 需要团队补充的条件

当前可继续准备评测，无需提供新的 API Key。后续真实资产影响需要团队自有或明确授权的组件清单及部署信息；独立验收需要来源核对的题单与复核人；决赛答辩稿需要主办方模板。缺少这些条件时，在验收表中保留待确认，不填写虚构结果。
