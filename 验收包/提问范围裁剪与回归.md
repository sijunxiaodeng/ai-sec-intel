## 修改后的行为

| 提问 | 返回内容 |
| --- | --- |
| 比较两条漏洞的评分和版本 | 分别列来源评分与范围，不自动追加修复、利用条件、技术影响；同版本基础分比较仍有来源及资产处置边界 |
| 只比较版本，或明确不要评分和修复 | 只列版本范围及引用，不排序评分；环境配置要求仍保留 |
| 明确请求利用条件和修复 | 条件与修复信息仍显示；缺少修复记录、未经测试及范围不能证明修复版本等说明保留 |
| 分别列评分，不排序 | 保留评分版本、来源及向量，不自动排名或列受影响版本配置 |
| 问政策适用范围和施行条款 | 从存档直接摘录完整第二条及末条，不调用模型、不添加第十二条 |
| 只问政策施行日期 | 保留施行条款和必要适用范围，不添加其他条款 |
| 明确请求第十二条 | 使用普通原文摘录路径，不能用范围/日期路径删除该条；范围及施行条款仍强制补全 |
| 多轮先问评分，再仅问版本 | 沿用已确认的漏洞实体，重新识别本轮字段，不把上一轮评分带入答案 |
| “不要遗漏版本”或“不要只列评分” | 视为保留/增加字段的表达，不能作为排除指令 |

有限的关键词与分句规则由 `agents/question_scope.py` 统一识别，字段组织及必需字段检查使用相同的正向问题范围。不把“不需要用户交互吗”等事实否定当成删字段指令。比较中没有可引用的所问事实时提示当前记录缺失，不拿其他字段替代；只有排除指令而没有明确比较字段时先要求明确范围。

政策直接路径只适用于资料均为政策、问题明确只涉及范围/施行条款的情况。带其他条款、要求或实际服务适用性的问题保留原检索路径；不据此判断具体服务是否合规。这是有限范围识别，不是通用语义理解或法规适用推理。

评分来源、CPE 包含/排除上界、预发布限定、否定与例外、强制政策范围及施行条款继续保留。上一轮的固定段落编号、跨块引用衔接及模型失败回退继续运行。
