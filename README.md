# AI 安全知识情报（赛题九）

三人共用的仓库。目前支持 NVD/OSV 漏洞监测、关联资料抓取与证据入库、结构化富化与影响说明、登记资产版本匹配，以及带来源引用的检索问答。

## 怎么打开系统

在本文件夹打开终端：

```
python -m pip install -r requirements.txt
python main.py
```

浏览器访问 http://127.0.0.1:8023 。页面里可以监测、查看富化、提问，并在「模型设置」里填写 DeepSeek 或通义千问的兼容接口。

接口约定见 `接口说明.md`。

## 当前验收入口

任务 C 的功能状态、比赛阈值、演示脚本和部署联调步骤集中在 [任务 C 验收包](验收包/README.md)。已完成开发链路；新文章通用关系处理、独立质量评测、另一台电脑部署和正式比赛材料仍按四阶段收尾。

启动系统后运行 `python -m questions.acceptance_snapshot`，报告写入本机 `data/`。该程序不调用模型或触发采集，只检查资料现状、接口和引用绑定，不据此判断比赛得分。

## 怎么重新采集

在本文件夹打开终端：

```
python collect_nvd.py
```

需要能访问 NVD，第一次可能要等一分钟。这是保留的早期静态采集入口；当前主系统的数据准备与联调按 [部署与联调](验收包/部署与联调.md) 执行，网页使用 `python main.py` 启动。

## 任务 C 的首日证据样例

在仓库根目录运行 `python -m rag.demo`，可离线演示 CVE-2024-37032 的富化样例、证据入库、检索和带引用的抽取式问答。它使用 Python 标准库，无须大模型密钥；样例明确标注人工整理，PoC 尚未由本项目复现。

运行和验收说明见 [rag/README.md](rag/README.md)。网页的「情报问答」现可载入历史样例，查看跨文档回答、片段引用及来源。

需要本地中文向量检索时，使用 Python 3.10 或更新版本，执行：

```powershell
python -m pip install -r requirements-rag.txt
python -m rag.prepare --semantic
python main.py
```

首次准备会下载模型。向量索引尚未就绪时，页面会明确显示使用 BM25。Windows 下载替代入口及测试方法见 [rag/README.md](rag/README.md)。

## 第三步：自动处理关联资料

打开「情报富化」，选择一条 CVE，点击「抓取关联资料」。页面会显示各来源的关联类型、抓取状态和片段数；随后可以在「情报问答」按这个编号提问。也可运行：

```powershell
python -m rag.ingest --cve CVE-2024-37032
```

这一步从现有参考链接和对应 NVD 记录发现资料，自动提取正文、分块、保存来源快照，并增量更新已准备的本地向量索引。未准备模型时仍可使用 BM25；不会在抓取或提问时下载模型。监测与公开源富化完成后，自动处理本批前 3 条情报，每条最多 4 个来源；其他情报可在详情页逐条处理。

完整原文、数据库、运行报告和模型留在被忽略的 `data/` 中。仓库只提交源码、接口与运行说明、离线测试。关联规则、支持范围和失败处理见 [rag/README.md](rag/README.md#第三步自动关联资料与证据入库)。

## 第四步：结构化富化与影响评估

完成关联资料抓取后，在「情报富化」选择对应 CVE，详情自动显示 CVSS 版本、分数、评分提供者与向量、受影响版本范围、攻击条件和技术影响、修复记录与 PoC 候选状态。每项事实附来源字段定位；「情报问答」也使用这些字段，例如提问「CVE-2024-37032 的 CVSS 评分、受影响版本和利用条件是什么？」。

报告读取本机已存档并校验 SHA256 的 NVD 响应，不额外联网、不需要大模型密钥。它保留所有有效评分，展示默认优先顺序为 CVSS 4.0、3.1、3.0、2.0，同版本优先 Primary；不同来源的评分不取平均分。NVD 收录的厂商评分保留真实提供者，不能统称为 NVD 自行评分。

版本包含/排除边界分别保留；版本范围的排除上界不直接认定为修复版本。PoC 候选只说明来源有 Exploit 标签，未运行；修复记录未由本项目测试。缺少资产清单与部署信息时，具体资产影响显示未知。目前不重新计算 CVSS 或环境评分。

接口 `GET /api/assessment/{cve_id}` 返回同一报告。测试命令：

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s questions -p "test_*.py" -v
```

报告字段与解释依据见 [接口说明.md](接口说明.md) 和 [rag/README.md](rag/README.md#第四步结构化富化与影响评估)。

## 第五步：登记资产并匹配版本

进入「资产影响」，粘贴或读取资产 JSON，选择 CVE 并点击「预览匹配」。可先「填入演示清单」查看 `CVE-2024-37032` 的三种结果：版本命中、未命中当前范围、版本待确认。演示组件为虚构记录，填入和预览不保存。

登记真实组件时使用确切厂商、产品和版本；保存后可评估已保存清单，或提问「我们的资产是否受 CVE-2024-37032 影响？」。导入按编号新增/更新，其余资产保留；资产和结果留在本机 `data/`。匹配不扫描目标、不运行 PoC，也不把资产清单发给大模型。

版本匹配当前支持数字点分范围及确切 CPE 限定，复杂配置或无法可靠比较的版本显示待确认。使用方法、字段模板与限制见 [资产清单说明.md](资产清单说明.md)。

## 第六步：多轮问答、漏洞比较与评测

「情报问答」支持连续追问、历史回答和开始新会话。例如先问 `CVE-2024-37032 的版本范围是什么？`，再问 `那应该怎么修复？`。明确新编号会切换上下文。比较时写出两条 CVE，回答分别引用证据；不同 CVSS 版本不直接排序。

新增 36 道开发评测题和独立运行程序：`python -m questions.evaluate --prepare`。报告留在 `data/`，分开记录规则检查、模型是否实际使用、完整本机 HTTP 耗时与人工复核结果。自动通过率不是赛题问答准确率。演示、评测和限制见 [问答评测说明.md](问答评测说明.md)。

## 第七步：国产模型接入与真实模型评测

可使用本机 Ollama 已安装的 Qwen，或自行配置国产云模型兼容接口。模型使用结构化回答和具体片段引用；空回答、截断、无效引用及关键字段问题会回退到证据摘录。网页明确区分模型回答、模型回退和规则回答。

模型模式运行 `python -m questions.evaluate --mode model --output data/qa-evaluation-model-report.json`。报告保存原始模型输出、采用/回退数量及逐题复核项，不将规则兜底结果冒充模型准确率。本机配置、限制和人工辅助事项见 [模型接入说明.md](模型接入说明.md)。

## 第八步：DeepSeek 对比与来源复核

已完成 DeepSeek 与本机 Qwen 的同版本 36 题真实调用对比，以及引用候选、复杂输出预算和事实条目上限的定向修复。结果分开记录完整对比、9 题复测和后续单题重测；密钥与原始模型输出留在本机。统计、来源复核发现与剩余问题见 [模型对比评测.md](模型对比评测.md)。

## 第九步：引用字段核对与系统状态分离

增加模型事实的结构化字段范围检查，拦截成因引用 SSVC、评分引用版本配置等错配。完整的小型 CVSS 字段进一步绑定评分、版本与提供者；项目验证与收录状态由程序单独追加，不引用为外部文献结论。规则范围、100 项测试及真实调用结果见 [引用核对说明.md](引用核对说明.md)。自由文本的完整语义仍需来源复核。

## 第十步：扩充知识来源与安全资料库

新增「安全资料库」，独立发现项目安全公告、研究文章和 arXiv AI 安全论文，支持没有 CVE 编号的资料。可同步、按类型筛选、查看原文证据，并检索「提示注入」「模型供应链」等主题。第十步当时只收录论文摘要，标准和政策法规未接入（第十二步已补充）；资料检索与原有漏洞问答分开，避免仅有主题关联的资料成为漏洞事实。

运行 `python -m rag.library --sync` 或使用网页「同步公开资料」。本机首轮收录 10 份资料、96 个片段，向量索引复用已准备模型；原有 6 小时任务增加资料同步。来源类别、关联规则、故障记录、119 项测试及后续范围见 [资料库说明.md](资料库说明.md)。

## 第十一步：把公告与研究建议接入漏洞问答

「情报富化」新增关联建议、来源归属和可展开的原文引用；使用「补充关联建议」刷新已知参考来源。问答可综合 NVD 版本范围、补丁记录和研究文章中的升级建议，逐项引用。例如询问 `CVE-2024-37032 应该升级到哪个版本？有哪些缓解建议？`。

项目公告的明确修复字段、研究方升级建议和本项目验证状态分开。仅主题相关或在背景中提到编号的文章不自动提供漏洞结论；模型改写来源归属或范围时回退摘录。已用 Ollama 研究文章和 vLLM 项目公告验证，141 项测试通过；真实模型调用的采用/回退统计及当前限制见 [关联富化说明.md](关联富化说明.md)。

## 第十二步：论文全文、官方参考资料与主题摘录问答

「安全资料库」现在可以单独获取 arXiv HTML 全文，监测两份正式政策正文、NIST 生成式 AI 风险框架和一份国标官方目录。每份资料明确区分摘要、全文文字、政策条文或仅目录，保留实际论文版本、条文/物理页码、原文日期和引用。

在资料类型中选择「政策法规」，勾选《生成式人工智能服务管理暂行办法》，点击「填入政策示例」和「按证据回答」。也可勾选论文全文与 NIST 框架，询问间接提示注入；程序分别组织有引用的原文。模型只挑选连续原文，改写或错引时回退；政策总会附完整第二条和施行条款。目前尚未生成自由比较结论或法规适用性判断。

本机当前共 17 份资料、589 个片段；新增两篇论文全文、两份政策、一个 PDF 框架和一个标准目录。165 项测试通过，实际页面及 DeepSeek 摘录验证完成。国标全文、跨文档推理及独立准确率验收仍待完成。使用、接口、来源边界和脱敏验证统计见 [全文与政策资料说明.md](全文与政策资料说明.md)。

## 第十三步：证据关系与限定跨文档分析

「安全资料库」新增「关系分析（间接提示注入）」和「填入关系示例」。把论文全文与 NIST 框架中的机制、检索/读入条件、可能影响、防护方向与局限、红队评估建议和来源引用关系连接起来，区分来源说明与项目限定综合；原文及限定条件可展开查看。

当前有 11 条核对过的关系说明、四类分析路径。关系绑定来源 URL、实际版本和片段摘要；原文改变或证据异常时停用对应结论。模型只选择现有路径，不能新增事实或宣称本项目已验证攻击/防护。其他主题继续使用原文摘录。

181 项测试通过；最终 14 道规则题、3 道真实模型题完成本机 HTTP 自动检查，模型题耗时约 0.75–1.03 秒。题单已公开给开发者，自动结果不是独立语义准确率，也不是通用多跳或负载测试达标证明。运行和审核方法见 [证据关系分析说明.md](证据关系分析说明.md)。

## 第十四步：模型供应链分析与关系候选审核

「安全资料库」增加「填入供应链示例」，对照 HF Pickle 加载风险与 NIST 第三方组件治理。新增 8 条来源说明、3 类限定综合路径；签名和扫描局限随引用保留，不判定具体模型文件安全。

「关系候选审核」可自动提出原文及分类、查看存档、通过/拒绝/撤销并保留审核历史。通过后仅进入独立的补充原文图，不自动成为综合推理前提；来源正文或版本变化后停用旧审核。候选及审核数据库只保存在本机。

195 项回归测试、23 道 HTTP 规则题和 3 道实际模型分析题通过自动检查，实际候选提取及页面复核已验证。独立语义准确率仍待验收。范围、操作、来源和复现方式见 [模型供应链与关系候选说明.md](模型供应链与关系候选说明.md)。

## 第十六步：新文章原文关系候选

「安全资料库」支持从勾选的新文章提取主语、原文关系、宾语和条件；目录不生成技术关系，摘要保留范围提示。模型输出需通过来源跨度及否定/情态词检查，新项全部待审核；通过项可查看带引用的关系图，来源或候选内容变动后停用旧审核。

215 项回归测试、23 道原主题 HTTP 规则题和 11 项验收接口检查通过；真实新文章已生成结构化候选并完成 2 条开发来源复核。这不代表通用跨文档推理或独立准确率已经验收。使用方法与边界见 [新文章关系提取说明.md](新文章关系提取说明.md)。
